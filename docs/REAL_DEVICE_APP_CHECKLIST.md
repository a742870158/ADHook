# 宿主应用真机排查清单

> 用途：统一真机回归口径，不把“已注册”“单测通过”或“日志出现”当作效果证据。逐项在目标设备上完成冷启动、热启动、页面动作和关闭回归后再填写结果。
>
> 底座 `HookDispatcher` 不注册任何专有宿主 Hook，作用域建议为空；宿主深度适配由独立插件提供，插件能力、宿主文档与验证状态由各插件项目维护。本页只提供排查顺序和记录位，不复制宿主合同。

## 一、统一真机执行口径

### 1. 前置记录

- [ ] 设备型号 / Android 版本 / 厂商 ROM：
- [ ] ADHook APK 版本、构建时间、签名身份：
- [ ] 宿主版本号 / versionCode：
- [ ] LSPosed 已启用模块，并勾选**实际测试包**作用域：
- [ ] 已关闭会干扰结果的其它去广告或代理工具：
- [ ] 测试前已强退宿主；需要清理数据时另行记录，不能把清数据后的结果当普通升级回归：

### 2. 每个宿主最小回归步骤

1. [ ] 冷启动：强退后启动，记录是否注入（包名、进程名、`HookDispatcher`/插件加载日志）。
2. [ ] 插件核对：确认目标插件已安装（安装即默认启用；底座无内置适配，未装插件就只剩通用层）。
3. [ ] 开关核对：Hook 在作用域内默认执行；只打开本次要测的插件 feature。
4. [ ] 首屏：观察开屏、启动路由、首屏广告/弹窗是否按文档处理，记录闪烁、白屏、卡死、返回栈异常。
5. [ ] 核心页面：按插件项目该宿主的“重点回归面”逐项进入，记录实际隐藏/折叠/协议清洗/数据改写结果。
6. [ ] 热启动与返回：从后台恢复、返回上一级、切换 Tab/Fragment，确认没有重复折叠、空白占位、错位或崩溃。
7. [ ] 关闭回归：关闭对应 feature，强退重开宿主，确认不再执行新动作；历史已清洗数据不要求热恢复，不能猜原值。
8. [ ] 失败证据：未命中时保留宿主版本、页面路径、截图/录屏、关键 Logcat 和 feature 开关快照；不要用“注册 OK”替代效果结论。

### 3. 结果标记

- `未测`：尚未在目标版本设备执行。
- `通过`：关键路径实际生效，且无明显回归；仍需记录版本和证据。
- `部分通过`：部分 feature 生效，或存在闪烁/时序/恢复等边界。
- `失效`：未注入、未命中或出现明确回归，需要进入修复队列。
- `暂未适配`：源码/元数据明确未实现的专有 feature；不要误报为 Hook 失效。
- `历史限定`：只有旧包现场证据，当前 API101/目标版本不能继承该结论。

## 二、故障分流（先定位再修复）

| 现象 | 优先核对 | 不要直接下的结论 |
|---|---|---|
| 完全没有 ADHook/宿主 Hook 日志 | 实际作用域、测试包名、APK 路径、模块是否启用、强退重开 | 不要先改宿主指纹；可能是未注入 |
| 有 `HookDispatcher` 但无插件加载日志 | 插件是否安装、框架是否支持 remote files、dex 是否发布、ABI/`minBaseVersionCode` 是否匹配 | 不要把“配置存在”当作授权或命中 |
| 有注册日志但界面无变化 | feature 内存快照与开关、动作计数、页面时序、当前版本证据 | 注册 OK 不等于效果成功 |
| 首屏有效、二次进入失效 | Activity/Fragment/View 复用、owner 归属、代次取消、热启动补算 | 不要用无限轮询或重复安装兜底 |
| 关闭后仍隐藏/留空白 | 是否强退重开、旧实例已被清洗、owner 是否只释放自身 | 不猜测未知原值，不恢复其它 owner |
| 双包只有入口包生效 | 作用域和实际承载包、配置/统计是否按实际包隔离 | 不把双包合并成一个配置 |
| 某功能历史有效但当前失效 | 宿主版本、稳定资源/协议/唯一指纹和当前日志 | 不回填旧混淆名、整数 ID 或 first-match |

## 四、事实来源与维护规则

- 专有适配入口以 [`HookDispatcher`](../app/src/com/adhook/core/HookDispatcher.java) 为准（当前为空，只做通用层）；框架建议作用域以空的 [`scope.list`](../app/resources/META-INF/xposed/scope.list) 为准，底座不再有内建授权目录。
- 每个宿主的功能边界、已退役能力和证据以对应插件项目的宿主文档为准；本清单只提供排查顺序和记录位。
- 设备侧动作（安装底座 APK、推送插件 zip、强退重开）每次都要单独授权；构建脚本和测试脚本都不自动操作手机。
- 本文的 `未测/通过/部分通过/失效` 不是代码自动推导结果，必须附宿主版本和现场证据；未执行真机验证不得写成“已修复”。
