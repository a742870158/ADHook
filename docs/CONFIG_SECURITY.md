# 配置服务、授权与恢复边界

执行通道与传播解释只维护在[Hook架构](<HOOK_RUNTIME.md>)。最新本地验证与未验收状态只见[工程状态](<QUALITY_AND_RELEASE.md#validation-status>)；本页维护配置合同，不从历史测试推断当前设备授权、框架消费或远端CI。

## 配置存在不等于授权

AppConfig、安装列表、订阅、执行开关与宿主Provider授权是独立状态。打开详情、创建配置、开启拾取器/Hook、导入备份不会自动授权。

| 调用者 | 全局读取 | 全局写入 | 包配置/规则/统计 |
| --- | --- | --- | --- |
| 模块自身UID | 允许 | 允许 | 任意合法目标包 |
| 用户显式授权的额外宿主UID | 允许 | 拒绝 | 仅仍通过授权校验的自有包 |
| 未授权/不可解析UID | 拒绝 | 拒绝 | 拒绝 |

Provider每次捕获真实Binder UID，通过PackageManager解析归属再执行纯权限策略，不相信来源包字符串；一个sharedUID包被授权不连带其它包。拒绝为空Bundle，不创建配置；授权内操作失败仍返回失败/空结果。

详情页提供显式宿主授权开关；只有用户在开关上确认后才写入私有授权记录。`HostAuthorizationStore.setUserAuthorized` 是组件级API，调用方仍须自行保证“用户显式确认”语义。独立私有授权绑定包、UID、证书SHA256，重装/换签名可能需重授权。撤销只撤Provider访问，不清配置或更改LSPosed/已注入Hook。私有授权不进规则备份或框架快照，不从旧配置推导。

底座没有内建宿主目录：`scope.list` 保持为空，实际框架作用域仍由用户在 LSPosed 中勾选，scope 与私有授权不是同一控制面。

## 执行快照与发布

- 每应用 Hook 默认关闭，缺失配置不自动开启。框架提前注册，回调只查内存总Hook与feature，UNKNOWN放行，不把关闭当零注入。
- 正式service101同版本提交启动v2与完整config；启动快照完整性标记独立于版本，同版本scoped/full仍须装载规则。
- 完整读取、刷新、Provider鉴权校准在后台；不保留XSharedPreferences/world-readable镜像或私有文件直读fallback，不开放公共文件写入口。主线程绝不Provider同步Binder。
- RemotePublicationState区分desired/published/error/attempts；保存、远程确认、宿主消费和效果不同。失败有限重试不回滚关闭意图，冻结时不承诺硬传播上界。
- remote-publication内容通知仅触发控制台重读，不是配置写入口；外部Intent仍只导航，拾取保存须鉴权Provider成功。
- 业务包装捕获包/特性并恢复嵌套上下文，非首包且不同UID库加载不覆盖宿主；sharedUID进程级singleton/统计限制仍需如实说明，不声称全部多包独立。
- 已被修改的历史磁盘原值、清洗数据/派生实例不猜测还原；明确owner可释放，其余建议重开。

## 统计与输入

只接受Provider真实UID鉴权上报，旧StatsReceiver已退休，没有备用写入广播。获授权宿主自报仅是诊断信息，仍可能谎报合法范围内的自身数据，不用于可信计费。

- 输入JSON最多16Ki字符，states/hits结构、状态枚举和整数计数严格校验；不隐式转换布尔/字符串/小数，不接受非法项后部分保存。
- 普通feature ID最多128字符，ASCII字母数字/._-；managed规则严格canonical `adhook:v2:` 四元组编码，最多4096字符并受整体预算。
- 每对象128字段、每UID至少1秒/60秒最多30份、256包上限；同UID不同包共享限额，内存/磁盘envelope也校验。
- 新会话按实际包/进程槽替换，跨槽有界聚合而非重复累加；旧裸快照保留“旧版记录”，截断/未采集/未上报分别显示。
- 客户端只有一个在途快照/有限尾批和退避，超限摘要限流，不打印完整payload；Provider不可用不走无鉴权广播。
- CustomRule在宽松反序列化前校验类型/边界/动作与精确textProperty、textMatchMode、trimText、Activity/资源约束；错误输入不降级成更广匹配。

## 外部详情与规则身份

AppDetailActivity允许外部导航，但只接受合法package_name定位已有数据。不处理pending_rule_json，即使同ID已存在也不例外；来源包/外部app_name不作权限或标签证据。onResume后台读现有快照，不隐式导入/授权；拾取先Provider保存，失败回跳不能补写。

picker、remote按来源独立；namespace/subscription/pkg/upstreamID决定身份，名字、简类名和资源尾名不是。旧同ID/payload歧义保留本地并持续提示，由用户确认去留。总开关不覆写逐条偏好，撤回只移除相应订阅投影，不删本地picker。

## UI、锁与存储

MainActivity仅导航/接线，屏幕负责渲染，Repository IO做包查询、图标、配置、订阅和文件；取消过期读取，失败不乐观显示成功。AppListRepository用detached只读快照，不调用创建型getter；缓存有界。

既有协调锁顺序：SubscriptionManager → ConfigManager → appConfigs map。ConfigManager不反调订阅，不持CM锁反向获取订阅锁。普通save的排队成功不等于磁盘提交，备份恢复在IO使用落盘屏障。

应用Hook/拾取器/原生特性开关、Provider拾取规则编辑及规则 Toast 偏好都在IO调用方等待本次同步落盘；失败恢复旧内存、不创建新应用、不推进desired版本。通用save仍是排队API，不能代替这些操作的成功确认。本地提交、远程发布和宿主消费仍分开报告。

IO调用方专用的saveSynchronously：先确认旧写入队列已完成，再同步提交本地文件；awaitWriteQueueIdle只表示队列已排空，不把上一次已完成失败变成永久禁止重试。屏障超时/拒绝时不排入新的提交任务，也不保证此前已经运行的写入被撤回。配置临时文件先设置owner-only权限并fsync，再ATOMIC_MOVE替换；原子移动不受支持或失败时拒绝，不删除旧配置文件作fallback。本地成功仍不等于远程框架确认；同步提交和导入成功后立即更新desired版本、失效本进程缓存、规则引擎与配置代次，各通知独立隔离故障。原子文件提交点之后的发布或通知错误不能把已落盘结果翻成“未保存”假失败。

普通JSON导入三种格式都先完整预校验并暂存（16Mi字符、解析前词法嵌套最多64层，字符串内括号/转义不算结构），非法后续条目不部分合并，已有开关及来源规则合并语义保留；本地原子提交成功才发布内存和成功文案。当前配置损坏时拒绝普通合并导入，需完整备份恢复或修复原文件；未保存不会假提示成功，也不会用默认值覆盖损坏材料。

损坏文件优先保存为adhook_config.json.bak，已有备份时使用独立时间戳/随机后缀，不删除或覆盖旧恢复材料。主文件缺失但损坏备份仍在（或目录不可确认）时，下次启动仍标记损坏并拒绝普通写入；修复主文件或显式完整恢复成功后才恢复可写。备份保留不等于自动恢复，不自动清理历史材料。

普通订阅新增/更新、启停、删除与规则偏好编辑捕获来源三文件的UTF-8文本/存在状态及完整来源内存；来源、迁移偏好、freshness元数据均先提交，配置投影作为最后同步提交。任一步失败恢复原来源和规则内存；回滚自身失败则保留旧内存、暂停后续订阅修改，并明确提示完整备份恢复，不假报成功。AtomicFile的finishWrite返回void，不能只凭无异常判定成功：fsync后完成写入，再读回一致确认。此流程是进程内尽力回滚，不是三文件跨断电事务；同步提交前的旧在途写入屏障未完成时拒绝，不宣称硬撤销已执行IO。

普通订阅下载和加载/恢复共用原始类型预校验：apps/rules存在时必须是数组（null也不是撤回），布尔/整数/文本约束不得经宽松反序列化丢弃。只接受完整JSON对象，16Mi字符/64层；规则目标、名称、Activity、父深及文本长度按现役CustomRule安全边界校验。合法空数组仍可明确撤回来源规则，非法后续项拒绝整份更新并保留旧状态。

ADHook 使用[有界订阅下载器](<../app/src/com/adhook/config/subscription/SubscriptionDownloader.kt>)：最多16MiB响应，校验声明长度和UTF-8；普通下载30秒总预算，最多4个并发、5次同来源重定向，允许同主机标准HTTP→HTTPS升级但拒绝降级/跨来源跳转。移除自动GitHub第三方镜像兜底；改变来源须用户直接选择并核对地址，不能把镜像HTTPS当原发布者认证。超时看门狗持有实际连接，取消/下载完成后及来源事务开始前复核；已开始的同步IO不承诺硬撤销或断电原子，来源HTTPS校验也不等于规则发布者签名认证。

订阅输入与配置投影由来源事务统一提交；跨管理器完整备份恢复的边界见下节，不另复制存储SOP。

## 应用内更新与安装请求

- [更新入口](<../app/src/com/adhook/util/UpdateChecker.kt>)只查询固定官方GitHub发布API；附件必须来自同一官方仓库HTTPS地址，下载重定向只允许显式GitHub资产CDN，最多5次，不再自动切第三方代理或失败后自动打开浏览器。
- 官方API必须提供合法SHA-256才启用受管下载；缺摘要仍可展示发布，但仅允许用户明确打开官方发布页。大小必须为整数且在预算内；元数据最多1MiB/20秒/64层，APK最多256MiB/120秒，连接/读取也有局部超时。
- 远端asset名字不作为本地路径：私有cache/updates目录拒绝符号链接，随机本地part文件完成长度、ZIP、官方hash与包名/递增版本/当前证书元数据比对后fsync并原子提升。单进程单下载，缓存最多8文件/256MiB，满额拒绝且提示清理缓存，不静默删除未知或可能供安装器读取的旧文件。
- 下载receipt在安装请求前再次核对受管路径、长度/hash、当前包/版本/证书元数据；请求取消/超时在各阶段拒绝成功交付并尽力清理本次文件，caller continuation的prompt cancellation也回收被丢弃receipt。网络/文件IO不可硬抢占，检查与系统调用之间不是跨线程事务，不保证同步调用立即终止或瞬态文件硬撤回。
- 包管理器给出的证书是**元数据比对，不替代APK密码学验签**；官方摘要验证、原证书集合不变及版本递增分别校验。最终验签和用户确认仍由系统安装器完成；签名轮换不自动接受。UI区分“需要安装来源授权”与“已打开系统安装器”，不称安装完成，无静默浏览器兜底。本轮未真实请求网络或操作手机安装/权限。

## 完整备份与失败恢复

- 备份包含配置、订阅与逐条偏好/归属；私有宿主授权不导入。
- 插件元数据只备份市场来源（id/name/url/enabled）与已安装插件（id/versionCode/enabled）；插件二进制、发布者信任钉扎（TOFU）和宿主授权绝不进入备份。恢复不会安装代码、不会信任发布者；备份中有但本机未安装的插件只标记“待重装”，不自动联网下载。
- 旧版备份字段缺失时按通用默认处理，不把缺字段视为空集合覆盖现有数据；恢复后仍按当前配置合同校验。
- 恢复前全量校验所有区块及类型，先创建恢复前磁盘快照，再按锁顺序受控提交。任一失败检查返回值并尽力回滚，不显示成功Toast；回滚失败保留路径供人工恢复。
- 当前损坏状态无法可靠导出快照时拒绝继续，原损坏文件/备份保留。跨多个管理器是进程内尽力恢复，不是断电级多文件事务。

## 插件安装、授权与信任

- 安装/启用/更新/卸载插件只改变插件目录与插件目录内的安装记录；不得写 AppConfig、不得授予宿主 Provider 授权、不得打开 Hook 开关。插件目标的授权仍由用户在应用详情显式确认。
- 市场来源身份是数值 id，URL 不是身份别名；同一 URL 返回不同发布者必须保留歧义并提示。来源列表与逐条启停独立于插件安装记录。
- 插件签名使用 ECDSA P-256/SHA-256；首次安装展示完整发布者指纹并由用户确认，之后按插件 id 钉扎 keyId/指纹。key 变化阻断更新；未签名包仅在开发者模式显式放行，市场安装永不 unsigned。
- 信任钉扎是私有安全状态：不进备份、不导入、不由 AppConfig 存在或插件列表推导。卸载保留用户配置与规则；“遗忘发布者”必须由用户显式操作。
- 插件目标不会自动获得授权；从旧版本升级的宿主需要用户重新授权；UI 提示但不静默迁移授权。

## 回归合同

权限矩阵/sharedUID、存在不授予授权、无创建读取、外部Intent注入、统计拒绝不落盘、逐来源偏好、完整启动快照升级、恢复前快照与失败回滚必须测实际调用链。插件安装不授予授权/不创建 AppConfig、备份不携带信任/授权/二进制、TOFU key 变化阻断必须测实际调用链。手工源码/纯AST断言不替代Provider/Repository/真实服务入口；最终本地/远端/设备结果分开报告。
